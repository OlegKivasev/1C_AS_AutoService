Начинай поиск с расширения.
Основную конфигурацию подключай для поиска исходного поведения и зависимостей.

Сначала ищи объект или процедуру по имени.
Читай найденную процедуру и необходимое окружение.
Расширяй поиск по мере обнаружения зависимостей.

Большие BSL-модули и XML читай диапазонами.
Для результатов поиска выводи путь, строку и короткий фрагмент.
Исключай .git, резервные копии и результаты прошлых задач.

Перед изменениями учитывай ../AGENTS.md и ищи известные ошибки через ../БазаЗнаний/index.jsonl.
Читай только релевантные карточки; подтверждённые решения и ожидающие проверки исправления ведутся раздельно.
Правила предотвращения из найденных подтверждённых карточек обязательны для затрагиваемого кода.
Для каждого нового или изменённого вызова проверяй наличие метода, его параметры и клиентский/серверный контекст именно в целевой форме или модуле. Не переносить имя метода из соседней формы без такой проверки.
Перед завершением запускай проверки известных ошибок для изменённых файлов: python "../БазаЗнаний/tools/kb.py" check --file "Расширение/путь к изменённому файлу". Для нескольких файлов повторяй --file; для ожидающей подтверждения карточки добавляй --include-pending.
Не считать правку готовой, если относящаяся к ней проверка известной ошибки не проходит.

Тесты в информационной базе 1С проводит пользователь.
Агент выполняет только проверки, не требующие запуска базы или подключения к ней.
Не запускать 1С:Предприятие или Конфигуратор, в том числе в пакетном режиме, для тестирования изменений.
Не создавать и не запускать тестовые информационные базы.
Разрешены проверки файлов без запуска базы: статический анализ BSL, проверка XML и целостности ссылок метаданных.
